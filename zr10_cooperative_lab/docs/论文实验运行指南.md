# 论文实验运行指南

> 分支：`research/ecp-rh-experiments`  
> 本指南规定从环境检查、baseline 调参、学习方法训练/验证、主测试、OOD、消融、敏感性、可扩展性、绘图到 ZR10 mirror 的推荐顺序。不要先看测试集结果再回头改方法参数。


选择规则固定为：

## 4. MAPPO / Safe-MAPPO（可选强学习 baseline）

学习方法不是本文主方法。建议在非学习主结果稳定后再训练，避免耗费大量资源后才发现实验定义仍在变化。

### 4.1 训练

训练场景只使用 manifest 中的 `train_learning_only`：S1/S2/S3/S5/S6。示例：

```powershell
python -m zr10lab.research.mappo_protocol train `
  configs/research/scenarios/S1_single.yaml `
  configs/research/scenarios/S2_staggered.yaml `
  configs/research/scenarios/S3_crossing.yaml `
  configs/research/scenarios/S5_cluster_split.yaml `
  configs/research/scenarios/S6_contention.yaml `
  --output runs/mappo/train_seed0 `
  --seed 0 `
  --updates 300 `
  --rollout-steps 256 `
  --checkpoint-every 25
```

Safe-MAPPO：

```powershell
python -m zr10lab.research.mappo_protocol train `
  configs/research/scenarios/S1_single.yaml `
  configs/research/scenarios/S2_staggered.yaml `
  configs/research/scenarios/S3_crossing.yaml `
  configs/research/scenarios/S5_cluster_split.yaml `
  configs/research/scenarios/S6_contention.yaml `
  --output runs/safe_mappo/train_seed0 `
  --seed 0 `
  --safe
```

建议最终至少多个独立训练 seed；不要只用一个训练随机种子得出稳定性结论。

### 4.2 只用 validation 选择 checkpoint

```powershell
python -m zr10lab.research.mappo_select `
  runs/mappo/train_seed0/mappo_seed0_training_index.json `
  --configs configs/research/scenarios/S4_boundary_handoff.yaml configs/research/scenarios/S8_maneuver.yaml `
  --seeds 2001 2002 2003 2004 2005 `
  --output runs/mappo/selection/mappo
```

Safe-MAPPO 同理，输出放到：

```text
runs/mappo/selection/safe_mappo/selected_checkpoint.json
```

checkpoint 选择同样采用 discovery-safe 词典序，不允许看 held-out test。

## 11. ZR10 实机镜像验证

### 11.1 先纯仿真确认同一配置

```powershell
python -m zr10lab.research.console `
  --config configs/research/scenarios/S4_boundary_handoff.yaml `
  --mode sim `
  --algorithm ecprh `
  --auto-run
```

### 11.2 再启用 mirror

只有在原平台的网络、角度符号、限位和急停均已独立验收后：

```powershell
python -m zr10lab.research.console `
  --config configs/research/scenarios/S4_boundary_handoff.yaml `
  --mode mirror `
  --algorithm ecprh `
  --arm `
  --auto-run
```

mirror 的定义必须保持：

```text
虚拟目标 / 虚拟检测 / 匿名跟踪 / 搜索状态 / 论文评价
                        ↓
                     调度器
                        ↓
                 A / E / Zoom 指令
                 ↙                ↘
          虚拟 PTZ（论文任务）     真实 ZR10（执行镜像）
```

真实 RTSP/YOLO **不进入**这篇论文的目标闭环。实机反馈只用于回答：真实设备是否能够跟随算法给出的 A/E/Zoom 指令、执行延迟/误差有多大。

## 12. 每一轮正式结果必须检查

1. `batch_status.json`：是否有失败 run；
2. `missed-target rate`：不能只看监视 loss；
3. `censored detection delay`：未发现目标不能消失；
4. `visibility_level_certification_rate` / `priority_certification_rate`；
5. solver timeout / MIP gap / P95 solve time；
6. per-scenario paired statistics：不能只看 overall；
7. 消融是否确实只改变一个模块；
8. OOD 是否确实改变噪声/模型误差；
9. raw CSV、metadata、manifest/hash、provenance 是否齐全；
10. 理论—实验一致性表中的每个主要主张是否已有对应证据。

完整 Monte Carlo 跑完之后，再更新 `docs/理论-实验一致性与评价协议.md` 的“当前实现/结果”状态，并据此决定最终论文中保留哪些贡献表述。
