# ZR10 总监视与控制中心

此模块在原平台上增加本机浏览器界面。Python 后台独占设备控制，页面负责监视、配置与提交动作；三维和视频资源都在本机，不需要把设备或视频连接到外部服务器。

## 1. 最容易上手的启动方式

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m zr10lab console --config .\configs\control_center.yaml
```

也可双击项目根目录的 `启动控制中心.cmd`。这会打开一个待机界面，默认选择仿真；在页面选择任务模式后点击“开始实验”。构造控制中心和打开页面不会连接或转动真实设备。仿真模式不需要 YOLO 模型或真实设备；预览画面明确标注为模拟视图。

选择实机可以使用页面的环境选择框，或在终端指定：

```powershell
.\.venv\Scripts\python.exe -m zr10lab console --mode hardware --config .\configs\control_center.yaml
```

实机开始按钮需要明确启用运动控制。请先用原有 `probe`、视频预览和单台小角度测试核对地址及角度方向。界面不替代设备机械限位、相机标定和实验台断电方式。

已有的运行命令可以逐次选择界面：

```powershell
# 打开窗口；页面建立心跳后开始本次实验。
.\.venv\Scripts\python.exe -m zr10lab run --config .\configs\four_zr10.yaml --duration 60 --ui

# 本次明确不打开窗口，即使配置中 enabled=true。
.\.venv\Scripts\python.exe -m zr10lab run --config .\configs\four_zr10.yaml --duration 60 --no-ui

# 界面监督的实机实验；按原策略配置开始。
.\.venv\Scripts\python.exe -m zr10lab run --config .\configs\four_zr10.yaml --mode hardware --duration 60 --arm --ui
```

不想每次输入 `--ui`，可以在实验 YAML 顶层加入：

```yaml
control_center:
  enabled: true
  open_browser: true
  video_enabled: false
  heartbeat_timeout_s: 3
  preview_fps: 6
  frustum_range_m: 200
```

`--ui / --no-ui` 优先于配置。`console --no-browser` 只打印链接，不自动弹窗；`--port 0` 自动选择空闲本机端口。浏览器链接含本次服务的访问令牌，重启后应使用新链接。实验结束后页面保留，可查看结果、修改配置或再次开始；终端 `Ctrl+C` 停止后台并保存记录。

界面中的持续时间为 0 时表示手动结束。无界面的原有 `run` 仍使用正的固定运行时长。

## 2. 设备监视、手动控制和初始化

每台设备同时保留三类信息，不能混为同一个数值：

| 信息 | 含义 |
|---|---|
| 目标 A/E、倍率和参数 | 操作者或策略请求的值 |
| 实际反馈 A/E、横滚、倍率、反馈年龄 | 从设备收到的数值；过期或未知状态会明确标出 |
| 命令状态与 ACK | 命令发送/回执结果；ACK 不代表已到位 |

在设备列表选择设备，在控制区输入本地 A/E 目标角，点击应用。输入的是绝对目标角，单位度，不是 SDK 速度等级。实际坐标方向仍由 `control.yaw_sign/pitch_sign`、零点偏移和安装姿态决定。目标倍率和焦距毫米是不同参数：只有提供了实测 `camera.focal_length_table`，才可以把倍率换算为毫米或提交毫米焦距动作。

“初始化”将设备指向配置中的 `initial_yaw_deg/initial_pitch_deg`，按开放且支持的参数设置初始倍率；它不是设备重启或恢复出厂设置。连接会读取实际姿态，不把配置初始值冒充设备当前状态。

手动操作单台设备后，该设备进入手动接管状态，其余设备仍按模式工作。点击“交回算法”解除接管；“停止本台”让该设备保持停机，直到明确交回或重新下发动作。模式切换和算法重载先暂停控制，完成后由操作者明确恢复。

动作同时受以下约束：

1. `action_space.enabled`：本次实验允许修改的维度；基础配置默认只开放 A/E。
2. `devices[].capabilities`：已核实固件支持的可选相机参数。
3. 角度/倍率限位、内参表范围以及新鲜遥测。

界面根据注册表生成参数控件并显示禁用原因。未核实支持的曝光、光圈、独立滚转等不能靠填写数值变成可执行功能。非幂等的拍照、录像切换、HDR 切换是单次触发，不会随角度控制周期反复执行。

控制中心禁止在会话中修改 `encoding`（视频编码参数），包括算法下发。分辨率或编码的变化会影响内参适用范围和视频时延；请结束实验，在外部修改编码后重新校验图像尺寸、内参及延迟，再开始新实验。参数仍保留在平台动作模型中。

“暂停”停止动作但保留会话；“恢复”明确继续；“结束实验”关闭会话并刷新 CSV；“急停”锁存停机状态，清除待执行动作，必须先解除再重新开始或恢复。软件不能保证在断网或断电后送达零速报文。关闭页面、浏览器冻结或心跳丢失时，后台自动暂停，页面重连不会自动恢复运动。浏览器长时间在后台被系统节流也可能触发这一暂停。

## 3. 视频与检测

预览可随时开关。关闭预览会停止界面的 JPEG 编码/传输和图片轮询；如果当前模式需要图像跟踪，后台仍保留用于算法的采集和检测。预览与检测使用同一视频源，页面读取独立快照，不消费算法的待处理结果。

手动/纯扫描模式可以在没有 YOLO 权重的情况下控制设备；开启视频只做预览。进入需要检测的模式时才加载配置的模型；找不到权重会明确报错。相机帧和检测框必须来自同一帧，过期图像显示为不可用，不能把最后一张图片一直当成直播。

仿真预览是根据模拟检测构造的示意画面，不是无人机真实视频，不模拟镜头画质、曝光、运动模糊或实际推理耗时。

## 4. 任务模式和算法接口

| 模式 ID | 功能 |
|---|---|
| `manual` | 手动控制，自动策略为空动作 |
| `hold` | 保持观测，不主动搜索或改变指向 |
| `localize` | 固定姿态定位，开启检测与融合但不主动转动，适合已知静态点验证 |
| `scan` | 成对扫描预定空间点或 ROI 网格 |
| `track` | 单台相机独立选择并持续跟踪本机画面中的目标，将其居中 |
| `center` | 中心跟踪定位，为目标安排多站居中观测 |
| `multi` | 多目标共享视场、设备分配和持续定位 |

`track` 不以成功多站定位为前提，但仍需要正确相机内参、角度方向、已知且稳定的倍率。它与 `center/multi` 的空间调度不同。真实空间扫描与定位需要经过验证的站点位置、安装姿态和相机标定。仅勾选 `calibration_verified` 不会执行标定；必须使用独立实测点验证。

预定扫描点优先于网格；要根据 ROI 自动生成扫描路线，请设置：

```yaml
policy:
  scan_points_m: null
  roi: {x: [100, 160], y: [-50, 50], z: [35, 85]}
  scan_grid: [3, 5, 2]
  scan_dwell_s: 2
```

新增模式不需要修改前端。先编写本地 Python 类：

```python
# examples/my_center_mode.py
from zr10lab.models import Action, Decision

class MyMode:
    def __init__(self, cfg):
        self.cfg = cfg

    def reset(self):
        pass

    def decide(self, context):
        # 输入包括本机遥测、检测、世界射线和估计轨迹，不包含仿真真值。
        # 这个例子保持参数不变；在此实现你的算法，并返回设备ID到Action的映射。
        return Decision({
            key: Action(key, issued_t=context.t, ttl_s=0.5, reason="custom_hold")
            for key in context.devices
        })
```

在配置中注册：

```yaml
control_center:
  modes:
    - id: my_mode
      label: 我的协同算法
      description: 自定义模式示例
      policy: examples.my_center_mode:MyMode
      requires_detection: true
      requires_calibration: true
      settings:
        my_gain: 1.0
```

`settings` 合并到该模式独立的 `cfg.policy` 副本，避免污染其他模式。修改算法后，在界面暂停并重新加载算法，或重新开始实验；不需要重装 Python 包。入口模块会重载，插件自己引用的辅助模块如需热重载，应由插件管理。未知模式和错误插件会明确报错，不会自动换成另一种算法运行。

## 5. 三维空间、视场与定位轨迹

新增的显示范围、ROI表单、自由平移及聚焦操作见[三维视角与范围操作](三维视角与范围操作.md)。默认按设备群大小取景，可在“范围设置”分别调整坐标框与任务观测区域。

场景使用原平台 ENU 坐标：x 东、y 北、z 上，单位米；场地局部坐标也可使用，但需一致记录。支持拖动旋转、滚轮缩放、俯视和复位，以及设备/ROI/视场/轨迹显示开关。

矩形图像对应四棱锥视场。后端使用：

```text
实际云台姿态 + 安装旋转 + 实际倍率对应的内参
→ 图像四角和边界像素去畸变
→ 相机射线转入世界坐标
→ 在指定显示深度截断并绘制
```

显示深度不是实际最大观测距离，不考虑建筑遮挡或检测器识别极限。没有新鲜姿态、倍率未知/变化中或未完成实机外参验证时，不能显示为有效实测视场。仿真和配置预览始终带来源标签。

参考 `CASSim_v2.0_optimized.zip` 的 ENU 轴、设备颜色、半透明视锥、光轴和轨迹展示概念。原仿真工程直接读取仿真视角/真值，本项目采用包含横滚、安装旋转、离轴内参和畸变的完整几何，目标位置来自融合估计。

轨迹区分真实定位更新与预测外推。预测点不能作为本周期持续多站定位成功的证据。误差和几何质量需要结合 `localizations.csv` 中残差、交会角、时间差和协方差分析。

## 6. 配置和记录

设备地址、位置、安装姿态、初始角度、机械限位、控制器参数、相机内参、模型和算法参数可在停止状态编辑。位置是世界模型的输入，不是设备可以通过命令改变的物理位置；修改它会影响坐标转换，必须结束旧会话再应用。

界面“应用配置”更新当前控制中心，“保存配置”另存完整配置，默认 `configs/control_center_saved.yaml`，并返回实际路径。下次用 `--config` 指向保存文件。保存的新文件使用已解析的模型路径，移动工程到另一台电脑后需重新检查模型位置。

每次实验仍在 `runs` 生成独立目录，沿用原有 11 张 CSV。手动操作、模式切换、暂停、急停和错误写入事件；设备反馈、算法/手动动作和真实命令结果分别记录。分析命令不变：

会话外的配置修改、查询等操作另记为 `runs/control_center_audit_*.csv`，不需要先开始实验。它是操作审计文件，不是可传给 `analyze` 的实验目录。

```powershell
.\.venv\Scripts\python.exe -m zr10lab analyze "runs/你的实验目录"
```

定位精度不能仅通过漂亮的三维图判断。仿真真值只用于评估；实机绝对误差仍需要独立位置真值和时钟对齐。

## 7. 模块位置

| 文件 | 责任 |
|---|---|
| `zr10lab/control_center.py` | 会话、状态机、手动/算法仲裁、心跳、控制与日志 |
| `zr10lab/console.py` | 本机 HTTP/API、认证、静态资源与窗口启动 |
| `zr10lab/control_modes.py` | 模式注册、独立图像跟踪、插件加载 |
| `zr10lab/scene.py` | 从遥测/标定构造三维视场数据 |
| `zr10lab/web/` | 页面布局、交互、视频和三维绘制 |
| `zr10lab/web/vendor/` | Three.js 固定版本资源、MIT 许可证和 SHA256 |

界面本身不增加 Python 第三方依赖；使用原有 NumPy/OpenCV 等包及 Python 标准库。浏览器需要支持 WebGL；无需 Node.js/npm。旧 Tk 只读监视器 `zr10lab monitor` 继续保留。
