# 多固定光电设备时间最优协同扫描覆盖实验

## 1. 实验边界

本实验研究固定式 ZR10 的严格几何覆盖：设备位置不动，只控制本地绝对 yaw/pitch；第一阶段固定 zoom，不读取目标位置先验，不读取 `SimulationWorld.truth()`。所有算法共享同一个 `CoverageProblem`、候选 viewpoint、FoV 覆盖矩阵、转台时间模型、初始姿态与 `CoverageTracker`。

核心指标为完整有效覆盖 makespan `coverage_completion_time_s`。当前为 **open-path coverage**，扫描结束不要求回到初始姿态。周期持续搜索实验应另行把末姿态到下一周期首姿态的转换时间计入。

严格覆盖与旧 `roi_*` 指标不同：单元只有在设备遥测新鲜、连接正常、固定倍率已知且稳定、点位于相机前方、投影落入 `fov_margin`、距离满足 `effective_range_m`、云台速度低于 `settle_rate_dps`，并连续满足 `settle_s + dwell_s` 后，才记为首次有效覆盖。第一阶段配置明确使用 `occlusion_model: none` 和 `detection_model: ideal_geometry`。

## 2. 已实现算法

- `FS`：Fixed Sweep，固定条带分区 + 固定蛇形扫描；工程规则基线。
- `EWP`：Equal Workload Partition，按估计服务时间平衡单元工作量，再局部集合覆盖。
- `CG`：Cooperative Greedy，评分为“尚未覆盖单元数 / 转动稳定驻留时间”，逐设备扣除同轮边际覆盖。
- `TVP`：Time-aware Voronoi Partition，以云台时间代价而非欧氏距离分区，并加入容量/makespan 平衡。
- `VGLS`：Viewpoint-Graph Local Search，初始解取 EWP/TVP/CG 中最优者，执行 2-opt、冗余 FoV 替换和瓶颈设备任务转移。
- `OPT`：小规模离线精确参考。每台设备对 viewpoint 子集用 Held-Karp 求最短 open route，再用分支定界组合多设备方案。达到规模上限时显式 `unsupported_size`，达到时间限时显式 `time_limit`，不会退化成启发式冒充 OPT。
- `Proposed`：仅提供接口，当前故意报错；在创新算法尚未定义前不伪造方法或性能。

原 `ScanPolicy` 是“两两成对扫描”，可作为 `legacy_pair_scan` 额外工程对照，但不能替代 FS。

## 7. 生成 benchmark 汇总

```powershell
python experiments\analyze_coverage_benchmark.py benchmark_runs
```

输出位于：

```text
benchmark_runs/benchmark_analysis/benchmark_runs.csv
benchmark_runs/benchmark_analysis/benchmark_summary.csv
benchmark_runs/benchmark_analysis/benchmark_detection_cdf.csv
```

统计至少包含：Tcov、Mean/P95 first-coverage latency、重复覆盖率、从 `telemetry.csv` 重算的实际转动量、设备完成时间、工作负载标准差、planning time、成功/未完成、solver 状态以及（存在经证明 optimal 的 OPT 时）Gap to OPT。

未完成实验的 Tcov 保持空值；不会把最大实验时长当作完成时间。同一 `scenario_id` 出现不同 `problem_hash` 时分析器默认拒绝横向排名。

Monte Carlo 验证默认从离散任务单元均匀重采样 10000 个静止目标位置，其发现时间直接取对应单元的首次有效覆盖时间，输出均值、P95、最大值和 CDF 数据。这用于验证理想静止目标条件下 Tcov 与最坏首次发现时延的对应关系，不代表运动目标搜索。

## 10. 日志与可追溯性

`coverage_cells.csv` 中每个单元仅在首次有效覆盖时写一行，含 `cell_id / xyz / first_covered_t_s / device_ids / viewpoint_ids / required_views`。

`cycles.csv` 的 `metrics_json` 保存严格覆盖指标，`diagnostics_json.policy` 保存：algorithm/version、problem_hash、planning_ms、当前设备-viewpoint、route progress、solver 状态、coverage fraction、done 和 termination reason。

`metadata.json` 保存完整解析配置、algorithm/version、scenario、environment/policy seed、problem_hash、覆盖假设和可获取时的 Git revision。

原始 CSV 不由分析程序修改；所有派生统计进入新的 benchmark analysis 目录。

## 11. 公平性规则

正式横向比较必须同时满足：相同 evaluation cells、candidate viewpoints、coverage matrix、transition-time model、initial pose、fixed zoom、completion threshold、设备配置；除 OPT 外使用相同明确的规划时间预算。`problem_hash` 是自动核验这些条件的第一道门槛。

OPT 是离线 oracle，不要求与在线算法相同计算时间。若 OPT `solver_status=time_limit`，分析程序不会把它当作经证明的全局最优来计算 Gap；只有 `solver_status=optimal` 才作为 Gap 基准。
