# ZR10 官方参数核对与实机覆盖实验接入

> 核对日期：2026-09-10。本文只把 SIYI 官网/官方手册能够确认的“产品级参数”写成默认或保护值；站点坐标、安装姿态、相机内参、角度零位/符号、时延和转台转向时间仍必须对每台实机标定，不能由官网参数替代。

## 3. 官网存在的 FOV 差异及处理原则

当前官网自身存在版本差异：

- 中文技术参数页：1X `D=69.5°`、`H=61.5°`；10X `D=7.95°`、`H=7°`；
- 英文技术参数页：无变焦 `D=79.5°`、`H=71.5°`；10X `D=7.7°`、`H=6.7°`；
- 官方 FAQ：`D=69.5°`、`H=61.5°`、`V=35.0°`。

因此不把任一更宽 FOV 当作所有批次的“绝对真实值”。`configs/coverage_hardware_common.yaml` 为预检采用保守 FOV：1X 水平 61.5°、垂直 35.0°；10X 水平 6.7°。其中 10X 垂直 FOV/内参为几何推导的 nominal 值，不是官方标定值。

正式论文/实机 benchmark 必须用每台相机在实际 RTSP 分辨率、固定 zoom 下标定得到的 `fx, fy, cx, cy, dist` 替换 nominal intrinsics。只要内参、ROI、站位、姿态或限位变化，`problem_hash` 就应变化，分析器不应把不同 hash 的会话做横向排名。

## 4. 官网不能替你确认的参数

以下参数**不能**从官网直接写成实机真值：

1. 四个站点在世界坐标系中的 `position_m`；
2. `mount_rpy_deg`；
3. 每台设备 yaw/pitch 的零位偏差与正负号；
4. 真实 RTSP 输出分辨率、裁切和畸变；
5. 每个固定 zoom 的实际内参；
6. 图像/姿态时间同步误差与视频延迟；
7. 覆盖研究所需的真实 `slew(angle)->time`；
8. `settle_s`、`settle_rate_dps`、实际到位容差；
9. 世界坐标 LOS 测量误差。

因此硬件模板故意设置 `calibration_verified: false`。这是安全门，不是缺失功能。网站参数确认之后仍应完成一次现场标定才能执行 `--arm`。

当前实验第一阶段采用：固定 1X 光学 zoom、无遮挡、理想几何检测、`required_views=1`、open path、四台设备固定位置。

## 6. 接入实机前的现场修改

打开 `configs/coverage_hardware_common.yaml`，逐台完成并修改：

```yaml
position_m: [...实测...]
mount_rpy_deg: [...实测...]
control:
  yaw_sign: ...
  pitch_sign: ...
  yaw_offset_deg: ...
  pitch_offset_deg: ...
camera:
  image_size: [...实际流尺寸...]
  intrinsics:
    - {zoom: 1.0, fx: ..., fy: ..., cx: ..., cy: ..., dist: [...]}
calibration_verified: true
```

如果第一阶段固定 1X，只需要保证 1X 的内参经过验证；可以保留 10X nominal 项但不要在实验中改变 zoom。若你实际固定在其他倍率，则必须标定那个倍率并同步修改 `fixed_zoom`。


```powershell
python -m zr10lab run --mode hardware --arm --config configs\coverage_hardware_ewp.yaml --output hardware_coverage
```

## 11. 推荐的第一次动作验收

第一次 `--arm` 不要直接跑正式 180 s benchmark。建议：

1. 清空任务区人员和障碍；
2. 将四台设备放到中性姿态；
3. 先把 `duration_s` 临时设为 10~20 s；
4. 首先运行 FS；
5. 肉眼确认四台设备 yaw/pitch 方向、限位和停止逻辑正确；
6. 检查 `commands.csv` 是否均为成功状态；
7. 检查 `telemetry.csv` 中实际转动方向与动作一致；
8. 检查 `coverage_cells.csv` 的首次覆盖时刻是否符合实际视场；
9. 再逐步恢复完整 ROI 和正式实验时间。

## 12. 正式数据前必须补做 slew-time 标定

官网没有提供可直接代入本论文 `transition_time` 的完整角度-时间表。当前 `25 deg/s` 只是所有算法共享的保守规划值。

正式实机结果前应测试若干角位移，例如：

```text
0°, 5°, 10°, 20°, 30°, 45°, 60°, 90°, 120°
```

对 yaw-only、pitch-only 和双轴同时动作分别测量“命令发出→角速度稳定低于阈值且进入到位误差带”的时间，形成 `measured_slew_table` 或进一步扩展为双轴模型。所有基线必须共享同一实测模型。

## 13. 为什么不能把 ±0.01° 直接写成 angular_std_deg

官网 `Angular Vibration Range ±0.01°` 是云台稳定/抖动指标，不等价于：

- 相机中心像素对应的世界 LOS 角误差；
- 安装外参误差；
- 编码器绝对角误差；
- 多站统一世界坐标的测角标准差。

所以配置仍将 `camera.angular_std_deg` 标为 PLACEHOLDER，必须用实测数据确定。对于当前纯几何覆盖，它不是完成判定的主要参数；以后做多站定位时才会成为关键误差模型。
