# 算法开发：输入、决策、动作和学习接口

## 1. 实验问题与模块边界

一个设备对应一个智能体。联合决策需要决定“哪些设备看哪些目标、各设备
指向哪里、需要什么倍率及其他已支持参数”。能在两张图中检测到无人机并不
自动意味着完成定位：两次检测还必须是同一目标，时间需要匹配，射线要有
足够交会角，站点位置/安装姿态/镜头内参必须正确，且定位结果应通过残差和
几何条件检验。算法的目标是持续创造这些条件，融合模块负责检验条件并估计轨迹。

数据流为：视频与遥测 → YOLO/可替换检测器 → 像素观测射线 → 跨站关联与定位
→ 轨迹估计 → `PolicyContext` → `Policy.decide()` → `Decision` → 安全控制与设备。
所有实验策略共享这一接口，仿真只替换传感器与设备实现。

`zr10lab/policies.py` 不导入仿真器、不读取目标真值、不操作 SDK。必须保持
这一边界，否则算法可能在仿真中“知道目标在哪里”，而在真实实验中无法运行。

## 2. 输入数据的含义

| `PolicyContext` 字段 | 含义 | 主要限制 |
| --- | --- | --- |
| `t / dt / step` | 当前单调时间、决策周期、步号 | 硬件时间不是 Unix/UTC 时间 |
| `devices` | 按设备 ID 索引的真实遥测/仿真遥测 | 应检查连接状态、反馈时间 |
| `detections` | 原始图像坐标下的检测框、置信度、时间 | local_id 不是跨站目标 ID |
| `rays` | 标定和时间匹配后得到的世界坐标射线 | 单条射线没有已知距离 |
| `tracks` | 融合得到的估计位置、速度、协方差和状态 | coasting 是预测，不是本帧定位 |
| `metrics` | 运行器提供的可观测过程指标 | 算法不能依赖仿真真值指标 |

坐标/角度约定必须跟随项目几何模块和配置说明。设备站位由
`DeviceConfig.position_m` 给出，安装姿态由 `mount_rpy_deg` 给出；云台角度
是相对安装基座的角度。请通过 `world_to_gimbal_angles` 转换，不要直接对
世界坐标求 atan2 后送往硬件，否则安装姿态会被忽略。

## 3. 动作及参数冻结

```python
from zr10lab.models import Action, Decision

actions = {
    "25": Action("25", yaw_deg=12.0, pitch_deg=8.0,
                 target_ids=("track-1",), reason="my_assignment",
                 issued_t=context.t, ttl_s=0.5),
}
return Decision(actions, diagnostics={"algorithm": "my_method"})
```

`yaw_deg / pitch_deg / zoom` 是绝对期望值。`None` 表示本周期不修改，不能把
None 替换成 0。`parameters` 容纳控制层注册过的其他 ZR10 参数；新增动作
必须同时实现参数定义、取值校验、设备能力映射及日志记录。不能直接向其中
放任意 SDK 方法名并自动执行。

```yaml
action_space:
  enabled: [yaw_deg, pitch_deg]
```

这个例子只允许两个角度参与决策。内置策略和学习接口不会输出冻结参数。
冻结参数需要在设备初始设置与实验配置中明确，并由遥测/设备能力确认。
即使打开 `zoom`，协同基线也只有在 `policy.auto_zoom: true` 时主动使用
`policy.tracking_zoom`；高级算法可以自行搜索倍率，但所有用到的倍率必须有
匹配当前分辨率、裁剪和畸变参数的内参。

## 4. 内置协同基线怎样工作

### 未发现目标时：共同扫描

空闲设备按基线长度优先成对，两个设备指向同一个世界网格点；不同设备对
可以扫描不同网格点。只给每台相机分配互不相交区域，常常只能得到单站检测，
无法形成空间定位。这里以设备对为搜索单位，主动制造共同可见条件。

扫描点由 `scan_points_m` 显式列出，或由 `roi` 和 `scan_grid` 生成。一个
扫描点只有在两台设备共同可达时才会执行。驻留计时从两台云台都到位开始，
受 `scan_settle_tolerance_deg` 控制。所有点不可达时返回
`scan_roi_unreachable`，便于从日志识别站位/安装角/ROI 配置问题。

网格点扫描不是对整个连续三维体积的数学覆盖证明。网格间距、相机视场、
运动速度和驻留时间需要结合实际目标速度设计，且应从日志评估覆盖盲区。

### 只有单站观测时：带标记的距离假设

单条射线只能说明目标在一个方向上。基线使用 `ray_search_distance_m`
构造临时假设点，引导另一站看向附近。记录于
`diagnostics.search_hypotheses`，并明确 `is_localization: false`；这类动作
的 `target_ids` 留空，不能算定位成功。真实距离与假设相差较大时，第二站
仍可能看不到目标，应使用多个距离层、更大搜索视场或基于极线的搜索策略。

### 已有估计轨迹时：共同视场与设备分配

`mode: center` 中，每个设备对一次跟踪一个目标，两台设备分别把目标置于
自身光轴中心。默认容差 `center_tolerance_deg: 0.5`。冻结轴无法实现居中时，
算法不会把“目标还在画面边缘”计为中心跟踪。

`mode: multi` 中，一个设备对可以同时负责多个目标。算法计算各目标相对于
每台设备的单位方向，取平均方向作为该设备的候选视轴，再逐目标通过真实
内参和畸变模型投影，检查是否落在带安全边缘的图像范围内。因此两个目标
可以同时位于两台相机的画面中，并由各自像素计算各自射线，无需逐个居中。

每个候选至少包含两台不同设备。束搜索联合比较：新增双站覆盖目标数量、
交会角质量、云台转动时间、切换惩罚、最短驻留时间。一个设备同一时刻只能
属于一个候选组，但一个候选组可以包含多个目标。重复覆盖同一目标只有很小
冗余收益，优先把可用设备用于更多目标的双站定位。

`Track` 短时丢失后，根据估计速度预测并继续瞄准；超过 `coast_timeout_s`
则退出跟踪候选并重新扫描。预测过程本身不代表获得新定位。针对快速变向、
长时遮挡，应进一步实现不确定性扩张搜索、变倍重捕、交接与信息增益策略。

### 配置示例

```yaml
policy:
  name: cooperative
  mode: multi
  roi:
    x: [60, 160]
    y: [-70, 70]
    z: [35, 90]
  scan_grid: [3, 3, 2]
  scan_dwell_s: 2.5
  scan_settle_tolerance_deg: 2.0
  max_shared_targets: 3
  max_assignment_targets: 8
  fov_margin: 0.06
  minimum_intersection_deg: 2.0
  prediction_horizon_s: 0.2
  coast_timeout_s: 2.0
  minimum_dwell_s: 0.8
  assignment_switch_penalty: 0.35
  coverage_weight: 3.0
  geometry_weight: 0.75
  slew_weight: 0.12
  candidates_per_pair: 8
  assignment_beam_width: 64
  ray_search_distance_m: 150.0
  search_hypothesis_ttl_s: 1.5
```

设备对/目标组合先筛选，再以有限束宽求近似解，避免实验循环出现不受控的
组合爆炸。该基线不是最优分配证明；目标规模增大时，可替换成整数规划、
拍卖、分布式共识、MPC 或学习算法，并记录算法耗时及超时比例。

## 5. 编写自定义策略

```python
from zr10lab.models import Action, Decision, PolicyContext

class MyPolicy:
    def __init__(self, cfg):
        self.cfg = cfg
        self.enabled = set(cfg.action_space.get("enabled", []))

    def reset(self):
        self.memory = {}

    def decide(self, context: PolicyContext) -> Decision:
        # 在这里读取观测、构造特征、调用优化器或网络。
        # 示范保持动作：不会改变任何参数。
        actions = {d.id: Action(d.id, issued_t=context.t)
                   for d in self.cfg.active_devices}
        return Decision(actions, {"note": "replace_with_your_algorithm"})
```

```yaml
policy:
  name: custom
  custom: my_package.my_module:MyPolicy
```

构造器接收 `LabConfig`，每回合调用 `reset()`，每步调用 `decide(context)`。
`examples/my_policy.py` 给出复用几何约束、只改变优先目标的完整示例。
也支持直接将 `policy.name` 写成 `my_package.my_module:MyPolicy`。
动态加载会执行本地模块代码，应只加载自己编写或已审阅的模块。

## 6. Gymnasium 学习环境

```python
from zr10lab.config import load_config
from zr10lab.learning import CooperativeObservationEnv

env = CooperativeObservationEnv(load_config("configs/four_zr10.yaml"),
                                 max_steps=500, max_targets=8)
observation, info = env.reset(seed=42)
while True:
    action = env.action_space.sample() * observation["action_mask"]
    observation, reward, terminated, truncated, info = env.step(action)
    if terminated or truncated:
        break
env.close()
```

动作按配置设备顺序排列，每台设备是 `[yaw, pitch]` 或 `[yaw, pitch, zoom]`，
一维展开后为 `2N` 或 `3N`。归一化 `-1/+1` 对应该设备配置的最小/最大值。
角度冻结时维度仍保留，掩码为 0，解码后强制输出 None。其他离散参数需
另写 Dict/MultiDiscrete 包装器，并复用控制层的参数注册与校验。

观测为 Gymnasium `Dict`。所有数值数组是 float32，掩码是 int8：

| 键 | 形状 | 每行字段 |
| --- | --- | --- |
| `devices` | N × 16 | yaw/pitch/zoom 归一化值、两轴速度/最大速度、连接状态、遥测年龄、站点 xyz/位置尺度、安装 rpy/180、fx/width、fy/height、roll/180 |
| `detections` | N × M × 8 | 中心 uv（-1..1）、框宽高/图像宽高、置信度、检测年龄、类别编号、时间不确定度 |
| `detection_mask` | N × M | 1 表示该检测槽有效；0 表示填充 |
| `tracks` | K × 14 | 估计位置 xyz/位置尺度、速度 xyz/速度尺度、位置协方差对角/尺度平方、测量年龄、状态、hits/100（截到100）、本步 measured、支持设备数量/N |
| `track_mask` | K | 1 表示该轨迹槽有效 |
| `action_mask` | 2N 或 3N | 1 允许动作，0 冻结 |

默认位置尺度 200 米、速度尺度 20 米/秒，可在
`learning_position_scale_m / learning_velocity_scale_mps` 中调整。
学习特征使用有限 Box：位置/速度限制在归一化尺度的 ±1000 倍、年龄最多
1000 秒、归一化位置方差最多 1000000，角度/速率和掩码按其定义范围截断。
极端离群值会被裁剪，数量记入 `info.observation_clipped_features`；融合
原始状态和实验 CSV 保留原值。正常配置下该计数应为 0。
轨迹状态 tentative=0、confirmed=1、coasting=-1。轨迹 ID 只在内部维护
槽位连续性，不作为模型输入；轨迹消失才释放槽位。超过槽位容量的观测会
按确定顺序截断，实验应配置足够容量并关注实际目标数。

默认奖励为“当前双站测量覆盖率 + 0.25 × 位置精度收益 − 转动成本”。
覆盖与精度用仿真真值评估，通过一对一匈牙利匹配避免重复轨迹重复获奖。
奖励函数可以使用真值，这是训练监督；观测、`env.context` 和 info 均不
包含原始真值位置/速度/身份。硬件实验没有这些真值奖励，必须使用过程
质量指标或外部测量系统作评价。不要把奖励分解或仿真评价结果重新拼接到策略输入。

监视任务默认没有自然终点，`terminated=False`；到 `max_steps` 返回
`truncated=True`。回合结束后必须 reset。相同配置、seed 和动作序列会
复现同一回合。`reset(seed=None)` 继续环境随机数流，不会每回合固定到
完全相同的噪声序列。

`env.context` 可以直接传给普通策略，再用 `env.encode_actions()` 编码，
从而在同一个环境比较学习算法与协同基线。示例：

```bash
python -m examples.train_random --config configs/four_zr10.yaml --steps 100 --seed 7
python -m examples.train_random --config configs/four_zr10.yaml --steps 100 --seed 7 --policy baseline
```

环境提供集中式动作向量。使用独立智能体或 CTDE 时，可以写包装器按设备
拆分观测与动作；应明确各智能体能共享什么信息，避免把集中式融合输入
误称为完全分布式观测。强化学习训练方法、网络结构和性能结论需要另行
设计和实验验证，随机示例仅验证接口可运行。

## 7. 建议比较的实验

固定随机种子、站位、模型、目标速度、丢帧率和时间偏差，比较 hold、scan、
cooperative 与新算法。建议分别报告首次发现时间、首次双站定位时间、持续
双站观测比例、目标轨迹中断次数/时长、位置误差、交会角分布、转动总量、
设备任务切换次数、决策耗时和信息延迟，而非只比较单一累计奖励。

多目标关联误配会直接污染分配：应保留检测与射线标识、融合拒绝原因和
轨迹状态，从日志回放判断错误究竟来自检测、时间对齐、标定、关联、滤波
还是决策。硬件参数、ROI 和标定调整后，应先运行仿真/记录回放和配置检查，
再开展可控的真实设备实验。
