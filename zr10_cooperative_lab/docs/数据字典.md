# 实验数据格式与指标定义

所有 CSV 为 UTF-8 BOM，便于中文 Windows/Excel 打开；逗号、引号、换行由标准 `csv` 模块处理。数值列不要混入单位字符。坐标为米，角度为度，速度为米/秒或度/秒；变量名包含单位。

## 共同字段

| 字段 | 定义 |
|---|---|
| schema_version | 当前为1；字段结构版本 |
| run_id | 本次会话唯一目录名称 |
| utc | 通过本次会话起点建立的UTC时间映射；不参与时间差计算 |
| t_s | 相对会话起点的实验时间，单调秒 |

`metadata.json.start_t` 是原单调时钟起点。硬件 `sample_t/capture_t/issued_t` 为同一进程时钟绝对值；与 `t_s` 比较前减去 start_t。仿真起点为0，加速仿真的UTC是模拟时间映射，不表示处理机器真实走过同样时长。跨会话不能直接比较绝对monotonic值。

## 逐表解释

| 文件 | 主要字段 | 分析用途 |
|---|---|---|
| telemetry.csv | device_id, sample_t, yaw_deg,pitch_deg,roll_deg,zoom, yaw_rate_dps,pitch_rate_dps, connected,sequence,source,age_s,raw_json | 每周期采样的设备状态；raw保留原始SDK角度、倍率确认时间、已知/稳定标记等 |
| telemetry_stream.csv | 与telemetry相同 | 实机每次姿态回调的原始采样记录，不按决策频率重采样；仿真为空 |
| detections.csv | device_id,frame_id,detection_id,capture_t,received_t,time_uncertainty_s,class_id,confidence,x1,y1,x2,y2,width,height | 所有提交到融合循环的原图检测；被拒绝的检测仍保存 |
| rays.csv | device_id,detection_id,capture_t,ox/oy/oz,dx/dy/dz,angular_std_deg,confidence,class_id,time_uncertainty_s,embedding_json | 通过时间/标定检查的世界射线，可离线重新融合 |
| localizations.csv | localization_id,measurement_t,x_m,y_m,z_m,device_ids_json,detection_ids_json,residual_m,min_angle_deg,condition_number,time_span_s,covariance_json | 本周期真正形成的多站几何测量，尚未等同于稳定轨迹身份 |
| tracks.csv | track_id,estimate_t,x_m,y_m,z_m,vx_mps,vy_mps,vz_mps,last_seen_t,hits,status,measured,device_ids_json,covariance_json | 持久身份的三维轨迹；必须按measured区分新测量与预测 |
| actions.csv | device_id,issued_t,ttl_s,yaw_deg,pitch_deg,zoom,target_ids_json,reason,parameters_json | 策略请求的动作，空数值是None/保持；不是实际到位值 |
| commands.csv | device_id,command_t,status,sent,ack,latency_ms,applied_json,error,action_json | 实机执行结果，协议ACK不是到位；仿真不发送SDK，因此此表为空 |
| events.csv | kind,payload_json | 连接/重连、陈旧观测拒绝、动作拒绝、SDK反馈、看门狗、视频推理诊断、超期、退出等 |
| cycles.csv | step,dt_s,work_ms,deadline_miss,detections,rays,localizations,tracks,measured_tracks,metrics_json,diagnostics_json | 每个实验周期的负载、任务指标与策略/融合诊断 |
| truth.csv | truth_id,x_m,y_m,z_m | 仅仿真真值，绝不输入决策与关联；实机该表仅有表头 |

`raw_json/parameters_json/diagnostics_json` 是规范 JSON 字符串，可使用 `json.loads` 解析。diagnostics 包含拒绝计数、歧义、候选截断及策略搜索假设等，方便追查为什么某周期没有产生定位。

telemetry是决策周期快照，telemetry_stream是适配器收到的逐次原始反馈。原始姿态同时保存在有界内存历史用于帧时刻匹配。UDP网络本身可能丢包；日志完整不等于设备发出的每个包都已被主机收到，分析时还需检查采样间隔和sequence。

## 指标口径

- `roi_instant_coverage`：ROI离散采样点中，被至少一个有效设备视场覆盖的比例。
- `roi_cumulative_coverage`：本次实验中曾进入至少一个有效视场的采样点比例。
- `roi_multiview_fraction`：本周期被至少两个视场覆盖的采样点比例；这是几何共视覆盖，不保证目标识别成功或射线交会质量。
- `measured_track_count / predicted_track_count`：本周期测量更新和纯预测的轨迹数。
- `localization_recall`：仿真真目标中，与本周期measured轨迹经互斥距离匹配成功的比例；默认距离门限10m可配置。
- `cumulative_localization_recall`：累计成功匹配“目标×周期”数/累计存在的“目标×周期”数。
- `position_rmse_m`：所有成功匹配样本的三维欧氏位置误差均方根。没有匹配时为null，同时记录 `evaluation_match_count`，不能视为零误差。
- `id_switches`：同一仿真真目标匹配到的持久轨迹ID发生变化的累计次数；该简化指标不是完整MOTChallenge指标集。
- `longest_localization_gap_s`：目标存在但未被measured匹配的最长连续时间近似。
- `work_ms / deadline_miss`：几何、关联、策略、指标、日志入队的CPU墙时及是否超出配置周期预算，不包含相机曝光、传输和完整识别链路延迟。

ROI采用5×5×5离散格点（125点）。它是可比较的采样覆盖指标，不是对连续空间体积覆盖的严格积分；改变网格分辨率前，应同时记录相应实验配置/实现版本。

## 持久化与完整性

每次会话在metadata中保存完整配置和运行平台信息，初始 `completed=false`。正常结束且写盘无异常后改为true。`manifest.sha256.json` 保存每张CSV的哈希；`analyze`首先校验，修改原始CSV后会拒绝分析。建议先复制到另一个目录处理衍生数据，不覆盖原数据。

日志队列溢出不会静默丢弃，而是使实验失败并进入停止流程。相机最新帧被新帧替换属于实时采样策略，并非CSV丢失；视频帧率与决策频率不同，不能根据detections行数当作完整视频帧数。

## pandas 分析示例

```python
from pathlib import Path
import json
import pandas as pd  # 可选分析库，自行安装，不是控制层依赖

session = Path("runs/你的会话")
angles = pd.read_csv(session / "telemetry.csv")
angles.pivot(index="t_s", columns="device_id", values="yaw_deg").plot()

tracks = pd.read_csv(session / "tracks.csv")
measured = tracks[tracks["measured"] == True]
for key, part in measured.groupby("track_id"):
    xyz = part[["t_s", "x_m", "y_m", "z_m"]]
    xyz.to_csv(session / f"derived_{key}.csv", index=False, encoding="utf-8-sig")

cycles = pd.read_csv(session / "cycles.csv")
metrics = pd.json_normalize(cycles["metrics_json"].map(json.loads))
print(metrics.describe())
```
