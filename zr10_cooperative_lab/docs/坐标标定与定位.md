# 坐标、标定、多目标关联与空间定位

本平台把“看到无人机”“知道它相对本机的视线方向”“确认不同站看到同一个目标”“算出三维位置”分为独立步骤。YOLO 给出类别、置信度和原图检测框；相机几何把框中心变成世界射线；关联模块选择可属于同一目标的异站射线；定位模块交会；滤波器估计连续位置和速度。识别类别不是身份，`local_id` 也不是跨相机 ID。

## 1. 统一坐标与角度

| 项目 | 约定 |
| --- | --- |
| 世界坐标 | 局部 ENU：x 东、y 北、z 上，单位米 |
| 世界方位角 A | `atan2(y,x)`，东为 0°、北为 90° |
| 世界仰角 E | `atan2(z,sqrt(x²+y²))`，抬头为正 |
| 相机/云台局部坐标 | x 前、y 左、z 上 |
| 图像像素 | u 向右、v 向下，原图左上角为原点 |
| 云台角度 | 已由设备适配层转换符号的 yaw、pitch、roll，单位度 |
| 安装姿态配置 | `mount_rpy_deg: [roll, pitch, yaw]`，顺序不要写反 |
| 旋转模型 | `R(yaw,pitch,roll) = Rz(yaw) Ry(-pitch) Rx(roll)` |
| 相机到世界 | `R_world_camera = R_mount @ R_gimbal` |

世界原点可选 25 号设备光心或场地内便于测量的位置。若使用 25 号设备为原点，它的坐标填 `[0,0,0]`；其余设备填光心相对坐标。这里的东/北可以是已测量的场地正交轴，但若没有对准真实东/北，应在实验记录中明确标注为“场地局部坐标”，不要声称已是地理 ENU。经纬度不能直接填入米制坐标。

每台设备的 `position_m` 是相机光心近似位置，不是交换机位置或机壳角点。云台旋转可能使光心发生少量平移；默认模型忽略这一“杆臂”效应，适用于其影响相对实验尺度足够小的情况。近距离高精度实验应测量杆臂，扩展 `pixel_to_world_ray` 的原点模型。

`mount_rpy_deg` 表示云台底座坐标到世界坐标的安装旋转。底座倾斜、倒装和方位偏置都应进入外参。设备 SDK 的符号、零位、机械限位和安装旋转是不同概念：SDK 符号先由适配层归一化，安装姿态再由几何模块变换。不要把同一偏置加两次。

```python
from zr10lab.geometry import world_to_gimbal_angles

# 计算“把目标放到画面中心”所需的本地角度。函数不截断机械限位。
yaw_deg, pitch_deg = world_to_gimbal_angles((15, 25, 40), device_config)
```

设备本身有俯仰机械范围，因此观测上方大区域时，是否需要倾斜/改变底座安装必须根据实际可达空间验证。将目标变换成云台本地角度后，超出限位即不可达，不能只因目标在世界坐标上方就假设能看到。

## 2. 单目标中心跟踪与多目标离轴定位

单目标跟踪时，策略通常令相关设备把该目标置于视场中心。单目只给出一条空间射线，不能直接获得目标距离；至少两台有有效基线的设备在足够接近的曝光时刻观测同一目标，才能完成空间交会。

多目标共享视场时，多个目标可以同时偏离中心。对每个原图像素 `(u,v)`，先按该倍率的内参和畸变去畸变，得到归一化坐标 `(x_n,y_n)`；相机局部方向为：

```text
d_camera = normalize([1, -x_n, -y_n])
d_world  = R_mount @ R_gimbal @ d_camera
ray      = origin + lambda * d_world, lambda > 0
```

因此不需要为了定位每个目标都单独转到画面中心。完整三维变换会正确处理安装倾斜和横滚，不能用“像素偏差 × 固定角度系数”替代。检测框中心是目标方向的近似；当旋翼轮廓或遮挡引起框中心偏移时，会表现为角度噪声。需要更高精度时，可把检测器扩展成机身关键点/中心估计器，保持 `Detection` 下游接口不变。

```python
from zr10lab.geometry import pixel_to_world_ray, triangulate_rays

# state_at_exposure 必须对应视频曝光时刻，通常来自遥测历史插值。
ray = pixel_to_world_ray(detection, state_at_exposure, device_config)
location = triangulate_rays([ray_from_25, ray_from_26], options=config.fusion)
print(location.position, location.residual_m, location.covariance)
```

不同相机分辨率可以不同，但每个检测的 `image_size` 必须匹配本机内参表。YOLO 的 letterbox/resize 应在检测适配层还原到原始视频像素。几何模块发现分辨率不匹配会拒绝定位，避免静默产生有偏轨迹。

## 3. 内参与变焦标定

每个实验使用的倍率都应有实测内参；同一分辨率的多个倍率可在配置内组成严格递增的表：

```yaml
camera:
  image_size: [1920, 1080]
  angular_std_deg: 0.15
  intrinsics:
    - zoom: 1.0
      fx: 1200.0  # 这里只是格式示例，不是 ZR10 实测内参
      fy: 1200.0
      cx: 960.0
      cy: 540.0
      dist: [-0.10, 0.02, 0.0, 0.0, 0.0]
    - zoom: 2.0
      fx: 2400.0
      fy: 2400.0
      cx: 960.0
      cy: 540.0
      dist: [-0.08, 0.01, 0.0, 0.0, 0.0]
```

上述数值只演示结构，不能用于实机定位。实际倍率表需由标定生成。`fx/fy/cx/cy` 和同长度畸变向量在倍率之间线性插值。超出已标定倍率范围直接拒绝；只有一行时只允许该倍率。插值只是工程近似，应在中间倍率上测量验证。如果光学变焦、数码变焦、电子防抖、裁剪或视频分辨率变化导致非线性成像，应增加标定点或扩展内参模型。自动对焦也可能改变等效内参，实验中应保持与标定一致，或把对焦状态纳入更高维标定表。

棋盘格建议流程：

1. 固定设备倍率、分辨率与对焦方式，测量打印棋盘格方格边长。
2. 拍摄 15～30 张清晰照片，覆盖四角、中心、不同倾斜和不同距离；最少有效图像默认 8 张。
3. 输入棋盘格内角点“列数、行数”。例如 10×7 个方格对应 9×6 个内角点。
4. 查看整体 RMS、逐图 RMS 与最大误差；高误差图像需要核查运动模糊、角点误检和尺寸错误。
5. 用未参与拟合的照片/控制点验证。重投影误差小不等于外参正确，也不等于绝对三维误差小。

```python
import json
from pathlib import Path
from zr10lab.calibration import calibrate_chessboard

result = calibrate_chessboard(
    sorted(Path("calibration/25/zoom_1").glob("*.png")),
    pattern_size=(9, 6), square_size_m=0.025,
)
Path("intrinsics_25_zoom1.json").write_text(
    json.dumps(result, ensure_ascii=False, indent=2), encoding="utf-8")
```

实现使用 OpenCV 的 `findChessboardCorners`、`cornerSubPix`、`calibrateCamera`、`undistortPoints` 和 `projectPoints`；畸变顺序遵循 OpenCV，常见五参数为 `[k1,k2,p1,p2,k3]`。参见 [OpenCV 官方相机标定与三维重建文档](https://docs.opencv.org/4.8.0/d9/d0c/group__calib3d.html)。

无需写 Python 的命令行入口（在项目根目录执行）：

```powershell
python -m zr10lab.calibration chessboard --images "calibration/25/zoom_1/*.png" --pattern 9 6 --square-m 0.025 --zoom 1 --output calibration/intrinsics_25_zoom1.json
```

输出 `config_intrinsics_row` 可在验证后复制到 `camera.intrinsics`；其中 `zoom` 是拍摄时由你固定的倍率，程序不会从照片猜测倍率。

## 4. 安装外参和站点坐标标定

先用测量仪器确定各设备光心在同一米制坐标系的位置，再用多个已知静止控制点拟合安装姿态。控制点应方向分散、包含不同高度；若还要求修正站点位置，需要不同距离的控制点。单方向、共线或所有点都很远会造成几何退化，不能靠增加重复观测次数解决。

每个控制点记录以下信息：目标真实 ENU 坐标、目标原图像素、曝光时的已归一化云台 yaw/pitch/roll、实际倍率。输入标定函数的相机射线必须先去畸变。

```python
from zr10lab.calibration import fit_mount_pose
from zr10lab.geometry import pixel_to_camera_ray, intrinsics_at_zoom

rays_camera = [
    pixel_to_camera_ray(pixel, intrinsics_at_zoom(device_config, zoom))
    for pixel, zoom in zip(pixels, zoom_values)
]
result = fit_mount_pose(
    control_points_enu_m=known_points,
    measured_camera_rays=rays_camera,
    gimbal_ypr_deg=measured_yaw_pitch_roll,
    nominal_position_enu_m=device_config.position_m,
    initial_mount_ypr_deg=(0, 0, 0),  # 该 API 的顺序为 yaw,pitch,roll
    fit_position=False,
)
if not result.success:
    raise RuntimeError(result.message)
yaw, pitch, roll = result.mount_ypr_deg
print("填入配置 mount_rpy_deg:", [roll, pitch, yaw])
print("验证角度 RMS:", result.rms_angle_deg)
```

`fit_position=False` 固定已测量光心位置，只优化 3 个安装旋转参数。`fit_position=True` 同时优化 3 个位置偏移，至少需要 6 个控制点，默认每轴偏移限制在 ±10 m。采用稳健非线性最小二乘，输出每组误差、Jacobian 条件数、参数协方差及可辨识性判断。参数协方差的旋转单位为度，位置单位为米；它基于局部线性化，不能覆盖控制点测量的所有系统误差。拟合成功仍需用独立点验证，并手动把批准的结果填入配置。函数不会自动宣布实机已完成标定。

建议分别保存每台设备的原始标定图像、控制点 CSV、内参 JSON、外参结果 JSON、仪器测量精度、安装日期和视频设置。设备挪动、镜头设置改变或支架受碰撞后应重新检查。

外参命令行接收下面的控制点 CSV 列，每行一个静止已知控制点观测；像素允许离轴。`yaw_deg,pitch_deg,roll_deg` 必须使用归一化后的云台本地角度，与实验遥测记录一致。

```csv
x_m,y_m,z_m,u_px,v_px,yaw_deg,pitch_deg,roll_deg,zoom
```

项目提供 `examples/calibration_controls_example.csv`，为默认 `configs/four_zr10.yaml` 的 `zr10_25` 生成的**合成演示控制点**。它可验证命令流程，不能应用到实机。以下命令应恢复示例安装姿态 `[roll=0,pitch=25,yaw=0]`：

```powershell
python -m zr10lab.calibration mount --config configs/four_zr10.yaml --device zr10_25 --csv examples/calibration_controls_example.csv --output calibration/mount_25_demo.json
```

要同时估计站点偏移，可加 `--fit-position --max-offset-m 2`；位置本已用测量仪器准确确定时建议固定。结果中的 `config_device_patch` 使用正确配置顺序，并保持 `calibration_verified: false`，避免把一次拟合自动等同于独立精度验收。几何退化时命令返回非零退出码，条件数等不可用值在 JSON 中为 `null`。

## 5. 时间同步是移动目标定位的前提

四条 RTSP 视频通过同一交换机到达主机，不代表四台相机同步曝光。数据包到达时刻、图像解码时刻、YOLO 推理结束时刻和真实曝光时刻不同。遥测响应也有网络和轮询延迟。

平台统一用会话单调时钟，保留接收时刻和时间不确定度，并使用曝光时刻附近的遥测插值。实机没有硬件时间戳或公共曝光触发时，应测量每条视频流的端到端延迟及抖动，配置估计值，并把无法消除的误差放入 `Detection.time_uncertainty_s`。不能把接收时间直接命名为精准曝光时间。

定位将“各站估计曝光时刻的差异”和“估计本身有多不确定”分别处理：

```text
time_span_s = max(t_i) - min(t_i)
temporal_std_m_i = max_target_speed_mps * (uncertainty_i + abs(t_i - fusion_time))
```

估计曝光时刻的跨度必须不大于 `fusion.max_time_skew_s`（默认 80 ms）；每站不确定度不得超过 `max_time_uncertainty_s`（默认 200 ms）。随后用目标速度上界 `max_target_speed_mps`（默认 20 m/s）把不确定时间内的潜在目标移动换成米制噪声，加入每条射线的权重/定位协方差。它让未经硬件同步的系统也能进行显式带不确定度的初步实验，但不保证高速目标精度。

例如估计不确定度 150 ms、速度上界 20 m/s，仅时间因素就对应约 3 m 的横向噪声，交会深度方向误差还可能更大。此时名义时间一致的射线可以被处理，但输出协方差应明显变大，不能当作精准同步观测。高速或高精度实验应测量实际延迟抖动、收紧不确定度门限；不能把不确定度或速度上界随意填成零来提高表面可用率。若确定静态控制点实验速度为零，可以明确配置速度上界为零。

目标速度 10 m/s、站间时差 80 ms，目标就可能移动约 0.8 m。云台转速 30°/s、姿态时间错配 20 ms，会产生约 0.6°视线偏差，远距离时可达到米级误差。高速云台/无人机实验尤其需要减小延迟和抖动。

射线角度噪声还会依据实际云台 yaw/pitch 角速度放大：把角速度乘以“曝光时间不确定度 + 姿态插值/近邻时间误差”，再与 `camera.angular_std_deg` 做平方和合成。这与目标移动造成的米制噪声分别计算；同一延迟同时影响运动云台方向和移动目标位置。该近似依赖遥测角速度可信，横滚动态/高阶角加速度和系统偏置仍需通过现场标定验证。

融合器对短延迟的历史定位采用当前速度作一阶搬移并放大协方差。它没有实现乱序量测平滑或运动补偿多视图交会；超过 `max_measurement_age_s` 的测量被拒绝。若后续追求高动态精度，可扩展曝光时间标定、基于速度的异步射线交会和固定时滞平滑器。

## 6. 空间交会与质量门限

每条单位射线 `d_i` 对应投影矩阵 `P_i = I - d_i d_iᵀ`。交会最小化点到各射线的加权垂直距离，求解三维位置。权重由角度标准差、置信度和估计距离决定；远距离相同角度误差对应更大的米制误差，因此通过三次距离更新做近似加权。

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| `max_time_skew_s` | 0.08 s | 各站估计曝光时刻跨度上限 |
| `max_time_uncertainty_s` | 0.2 s | 单站曝光时间估计不确定度上限 |
| `max_target_speed_mps` | 20 m/s | 将时间不确定度转换成空间噪声的速度上界 |
| `min_ray_angle_deg` | 1° | 所用站对最小锐夹角；近反平行同样拒绝 |
| `max_condition_number` | 1e6 | 信息矩阵条件数上限 |
| `max_residual_m` | 3 m | 各射线垂直距离的 RMS 上限 |
| `max_angular_residual_deg` | 1.5° | 单条射线角度残差上限 |
| `min_depth_m` | 0.1 m | 交点必须位于每台相机前方 |
| `max_range_m` | 5000 m | 工作距离上限，可按场地收紧 |
| `measurement_floor_m` | 0.05 m | 防止权重无限大的米制噪声下限 |

任何门限失败都会返回可记录的拒绝原因，不能用 NaN 或任意远处交点充数。多站支持采用保守原则：所用任意站对都须超过最小夹角。增加一个与现有站近乎平行的冗余站可能被拒绝，但融合器仍可保留有效站对定位。

返回 `Localization` 包括位置、3×3 协方差、所用设备和检测编号、残差、最小夹角、条件数、时间跨度。协方差是测量模型内的局部估计，没有完整计入站点测量误差、安装偏差、镜头热漂移等系统误差。请使用场地真值验证绝对定位精度。

## 7. 多目标关联与轨迹状态

基线关联先枚举异站观测对，对可交会的站对增加其他站兼容观测；类别只排除不同类别，完全不读取仿真真值 ID。若检测器提供可比较的外观 embedding，可以使用余弦距离门控。已有轨迹通过恒速度 Kalman 预测，与空间候选做距离/马氏距离门控及匈牙利分配，随后强制每个观测只分配给一个轨迹。假设之间存在共享检测时采用受预算限制的近似冲突解决，因此不是全局最优的 MHT。

| 参数 | 默认值 | 用途 |
| --- | ---: | --- |
| `max_rays` | 80 | 单轮最多进入假设生成的射线数 |
| `max_hypotheses` | 300 | 候选定位数量预算 |
| `max_pair_evaluations` | 2000 | 站对组合计算预算 |
| `association_angular_gate_deg` | 1.5° | 向候选增加其他站观测的角门限 |
| `appearance_cosine_gate` | 0.4 | 有外观向量时的余弦距离门限 |
| `track_gate_mahalanobis` | 16.27 | 三维位置创新的平方马氏距离门限 |
| `track_gate_distance_m` | 30 m | 额外的物理位置距离门限 |
| `process_accel_std_mps2` | 3 m/s² | 每步未知恒加速度的标准差 |
| `initial_velocity_std_mps` | 10 m/s | 新轨迹初始速度标准差 |
| `max_measurement_age_s` | 0.5 s | 到达本轮时允许的最大观测年龄 |
| `confirmation_hits` | 3 | 进入 confirmed 状态需要的测量命中数 |
| `track_timeout_s` | 2 s | 距最后真实测量超过此值则删除轨迹 |
| `birth_merge_distance_m` | 1 m | 抑制同轮极近重复候选建轨的距离 |
| `ambiguity_margin` | 0.15 | 相近候选质量的歧义判据 |
| `ambiguity_distance_m` | 2 m | 歧义候选需要具有的空间分离 |

`birth_merge_distance_m` 是基线启发式。如果无人机间距可能小于 1 m，应调小它，并同时改善角度精度和关联模型。不同站同类别目标几何上可能产生多个可行交点，尤其是两站和多目标近共面时。模块会输出 `ambiguities`、`ambiguous_count` 和替代假设数量；歧义下选择的身份不能宣称可靠。需要更强的身份连续性时，应增加可比较外观特征、历史轨迹门控、第三站视角、JPDA/MHT 或设计主动消歧动作。

轨迹状态有 `tentative`（新建未确认）、`confirmed`（有足够真实命中）和 `coasting`（本轮没有真实定位、仅预测）。`Track.measured` 明确区分测量与预测；预测期间 `device_ids` 为空，`last_seen_t` 不更新。评价连续定位可用率时应按真实观测统计，不能把滤波器外推点当作持续多站观测成功。轨迹协方差顺序为 `[x,y,z,vx,vy,vz]`，位置米、速度米/秒。

同一 `(device_id,detection_id)` 在记忆窗口内只处理一次，防止重复使用旧帧。未匹配的新射线短时保存在缓冲区，以支持站点异步到达；超过观测年龄门限自动丢弃。相机重启导致帧编号重用时，应为帧编号增加流会话前缀或明确重置融合器。独立实验或 Gym 回合开始时调用 `FusionEngine.reset()`。

## 8. 验证顺序与可扩展点

先使用软件测试验证坐标变换、畸变投影、变焦插值、交会门限、关联互斥和轨迹生命周期，再用静态已知点验证实机。建议先固定倍率和云台姿态验证多站定位，再开启慢速中心跟踪，最后逐步加入多目标共享视场、变焦与动态任务分配。

现有测试使用原始空间点生成像素/射线，但把真实身份留在测试断言侧，不送入算法；包含共面多解案例，明确检查歧义诊断。合成数据测试验证的是数学和软件行为，不能替代四台实机的时序、标定、网络和视频验证。

扩展高精度实验时，优先评估这些误差源：曝光时间和云台姿态对齐、安装姿态和站点光心测量、实际倍率/对焦成像模型、目标框中心偏移、云台运动杆臂，以及跨相机身份切换。可以在既有 `Ray`、`Localization` 和 `Track` 契约后替换算法，而不需要修改设备控制和记录模块。
